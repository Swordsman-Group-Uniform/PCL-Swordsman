## 2. 这一轮改了什么（6 项）

### 2.1 品牌重命名：CE → Swordsman

- 标题栏徽标：`Plain Craft Launcher 2\FormMain.xaml` 里原来的 `Path`（CE 字形）+「For」+ 图片，
  换成单个白底圆角 `Border` + `TextBlock Text="Swordsman"`（FontSize 9 / SemiBold），
  位置 `Margin="10,0,0,16.6"`，与 PCL 墨迹底边（标题栏高 48）对齐。
- 项目名 4 处统一为 `Plain Craft Launcher 2 swordsman`：窗口 `Title`、`.csproj` 的 `AssemblyTitle`/`Product`、
  `metadata.json` 的 `name`、`PCL.Core/Utils/OS/AumidHelper.cs` 的 AUMID `DisplayName`。
- **`AssemblyName` 保持 `Plain Craft Launcher 2`**：`pack://application:,,,/Plain Craft Launcher 2;component/...`
  这类资源 URI 依赖它，改了会导致图标/图片加载失败。
- 复测点：标题栏显示 `PCL [Swordsman]`；任务栏/通知区的应用名；开始菜单快捷方式名。

  （缩放 1→1.07、叉的透明度 0.9→0.45，`SineEase` 双向，`Loaded` 启动 / `Unloaded` 停止）。

### 2.6 插件系统 M1 + 完整插件管理界面

这是这一轮工作量最大的部分，建议直接看 `docs/PLUGIN-SYSTEM.md`（17 节完整设计）。
要点：

- **两个新工程**：`PCL.PluginSdk`（契约：`IPlugin` / `IPluginContext` / `IPluginConfig` / `IPluginLogger` /
  `PluginManifest` / `PluginCapability` / `PluginState` / `PluginApiVersion = 1` / `PluginException`）、
  `PCL.PluginHost`（加载器：`PluginManifestReader` / `PluginLoadContext` / `PluginLoader` / `PluginInstaller` /
  `PluginStateStore` / `PluginHostManager` / `JsonPluginConfig`）。
- **宿主桥**：`Modules\Plugins\PluginHostBootstrap.cs`，在 `FormMain` 完成 `HardwareInfo` 初始化后调用 `Start()`
  （后台线程，先清待删除队列再扫描），暴露 `HostVersion` 与 `PluginsDirectory = <exe 目录>\PCL\Plugins\`。
- **目录约定**：插件本体 `PCL\Plugins\<id>\`，插件私有数据 `PCL\PluginData\<id>\`，
  状态文件 `plugins.state.json`，卸载队列 `pending-delete.json`。
- **管理界面**：完全照搬「实例设置 → 模组」页（`PageInstanceCompResource`）的布局与交互 ——
  搜索框、管理条五按钮（重新扫描 / 打开文件夹 / 选择文件安装 / 下载新插件 / 全选）、
  筛选单选（全部/已启用/已禁用/出错）、排序、列表、底部多选操作栏（启用/禁用/删除/取消）、空状态卡片。
  列表项是新控件 `Controls\MyPluginItem.xaml`（44px 行高、左侧色条、`lucide/puzzle` 图标、右侧电源/文件夹按钮）。
- **筛选计数规则**（照抄模组页）：`全部` 永远显示；`已启用`/`已禁用`/`出错` 为 0 时隐藏；
  当前选中的筛选一旦归零，自动顺延到还有内容的那个（优先级 已启用 > 已禁用 > 出错 > 全部）。
- **删除语义（重要）**：.NET 的 `AssemblyLoadContext.Unload()` **不会立刻释放 dll 文件句柄**，
  运行中直接删目录必然失败。所以删除是「**立即隐藏 + 下次启动彻底删**」：
  1. 禁用插件 → 2. 目录名写入 `pending-delete.json` → 3. 重扫时加载器**跳过**这些目录（列表立刻消失）
  → 4. 后台尽力立即删一次（GC + 重试）→ 5. 下次启动 `ProcessPendingDeletes()` 真正删除并清空清单。
  只弹一条成功提示 `已删除 N 个插件，文件将在下次启动时彻底清理。`
- **示例插件**：`samples\HelloPlugin`（id `sgu.sample.hello`），`samples\README.md` 写了如何编译安装。
- **调试钩子**：环境变量 `PCL_FORCE_PLUGIN_PAGE=1` 启动时直接进入插件管理页。

## 3. 上游同步：真实基点与下一版怎么同步

### 3.1 真实基点（这条很重要，文档曾长期写错）

本仓库的代码与上游 `dev` 分支 **`d1149d5`（2026-10-24，2.15.1 正式版之后 4 天的 dev 快照）**
1035 个文件逐字节相同，只有 65 个文件是我们的下游改动。

因此：**`v2.15.1-beta.1` 这个 tag 比我们的代码更旧**，不要拿它当同步目标 —— 那样会让 73 个纯上游文件回退，
丢掉 2.15.1 正式版的修复（包括 #3673「中国大陆地区禁用 MC 安装」）。`metadata.json` 里曾写的
`upstream: 2.12.1` 是上游自己「继承自原版 PCL2」的字段，不代表我们的代码基点。

### 3.2 下一版同步流程（建议）

1. `git clone` 上游仓库，checkout 目标 commit（建议取新的 `dev` 或正式 tag）
2. 用 `_tools\cmp2.mjs`（两棵树逐文件比对）找出差异文件
3. 差异分三类：**只有上游改** → 直接取上游；**只有我们改** → 保留我们；**两边都改** → 手工三方合并
4. 下游改过的文件清单见 `docs/HANDOVER.md` §5（`ModLaunch.cs`、`ModDownloadLib.cs`、`PageSetupUI.xaml`、
   `ThemeService.cs`、`UpdateManager.cs`、`ProfileUi.cs`、`Secrets.cs`、`Lobby*.cs`、`EasyTierEntity.cs`、
   `PageToolsGameLink.xaml(.cs)`、4 个语言文件等）
5. 合并后至少验证：编译 0 错误 → 启动 → 反馈/更新页仍是占位 → 主题只剩蓝色 → 插件页仍可用
6. 细节流程写在 `docs/HANDOVER.md` §4.2

## 4. 构建与发版

### 4.1 Windows（推荐，本机验证用的就是这条）

```powershell
# 需要 .NET SDK 10（本机 10.0.402）
powershell -ExecutionPolicy Bypass -File tools\build.ps1
# 产物：artifact-x64\PCLCE For SGU 27.1-snapshot-8(2.15.1).exe
```

`tools\build.ps1` 做的事和 `build.sh` 等价：读 `metadata.json` 拼版本号 → `dotnet publish -c Release`
→ 把产物重命名为 `PCLCE For SGU <完整版本号>.exe`。

> ⚠️ **该脚本必须保存为 UTF-8 with BOM**。Windows PowerShell 5.1 对无 BOM 的 UTF-8 会按 GBK 解码，
> 中文注释可能把行尾换行吞掉，导致 `param` 块解析失败（已实测踩过）。

### 4.2 Linux / Termux

`./build.sh x64 Release`（需要 `bash` + `python3`）。它只做同样的三步，产物命名规则一致。

### 4.3 发版前自检（`docs/HANDOVER.md` §3.4）

1. `metadata.json` 四个字段一致：`base` / `suffix` / `upstream` / `code`（code 必须递增）
2. 产物文件名 = `PCLCE For SGU <base>-<suffix>(<upstream>).exe`
3. 用 `strings` / `grep -a` 抽查 exe 内嵌字符串：新版本号存在、旧版本号 0 命中、
   `此版本不支持更新`、`下游项目声明`、`Swordsman`、`TerraCotta` 都在
4. 双击启动：无遥测弹窗、反馈页是占位、更新页是占位、主题只有蓝色
5. 如果改了 XAML：确认打包资源（`pack://`）没坏 —— 图标能正常显示就是通过

### 4.4 版本号怎么改

`Plain Craft Launcher 2\metadata.json` 一个文件说了算：

```json
{ "base": "27.1", "suffix": "snapshot-8", "upstream": "2.15.1", "code": 531, "name": "Plain Craft Launcher 2 swordsman" }
```

规则：**下游号（`27.1`）通常不变**，每轮发布把 `suffix` 递增、`code` 递增；
只有「我们的改动本身构成新的下游大版本」时才动 `base`（见 `VERSIONING.md`）。

## 8. 这一轮踩过的坑（给下一个人省时间）

| 坑 | 现象 | 解法 |
| --- | --- | --- |
| `build.ps1` 编码 | 报 `param` 语法错误 | 存成 UTF-8 **with BOM** |
| 单文件解包缓存 | 双击无反应，事件日志 `Failure extracting contents of the application bundle` | 删 `%TEMP%\.net\PCLCE For SGU 27.1-snapshot-8(2.15.1)\` 再启动 |
| `MyButton.Click` 签名 | XAML 报「无法从文本 Xxx_Click 创建 Click」 | 是 `(object sender, MouseButtonEventArgs e)`，不是 `RoutedEventArgs` |
| `MyIconTextButton.Click` | 同上 | 是 `(object sender, ModBase.RouteEventArgs e)` |
| `MyRadioButton.Check` | 同上 | 是 `(MyRadioButton sender, bool user)` |
| `MyCheckBox.Change` | 同上 | 是 `(object sender, bool user)` |
| 后台线程摸 UI | `InvalidOperationException: 调用线程无法访问此对象` | 插件事件在后台线程触发，进 UI 一律 `ModBase.RunInUi(...)` |
| `System.IO` | 新文件里 `Path`/`File` 未定义 | WPF 工程隐式 using 不含 `System.IO`，要显式 `using System.IO;` |
| 插件删不掉 | `Directory.Delete` 抛 `IOException` | ALC 占用文件，见 §2.6「删除语义」；不要绕开 `PluginInstaller` |
| 工具页跳子页 | `FormMain.PageChange(PageType.Tools, 子页)` 跳不动 | `PageChangeActual` 会用 `frmToolsLeft.pageID` 覆盖，必须直接调 `frmToolsLeft.PageChange(...)` |
| 事件订阅重复 | 页面多次加载后重复弹窗 | 订阅前先 `-=` 或者只在 `PageLoaded` 里订阅一次 |
| PS 批量改文件 | 中文注释乱码/文件被写坏 | Windows PowerShell 5.1 读写 UTF-8 无 BOM 会按 GBK 处理；批量脚本要带 `-Encoding UTF8` 并校验替换命中数 == 1 |

更多长期有效的坑（含 XAML 布局、`MyCard.IsSwapped`、`MyTextBox` 最小高度 28 等）见 `docs/HANDOVER.md` §8。
