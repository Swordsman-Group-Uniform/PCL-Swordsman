# 死规矩：遇到任何问题，**先读日志，再动代码**

> 这条规矩是 2026-10-29 用三轮白折腾换来的：
> snapshot-35 / 36 / 37 三次「修磨砂框比界面大 + 圆角消失」，全是**凭猜测**改代码 ——
> 改边距、改坐标系、改布局时序，一轮一个说法，问题一直在。
> snapshot-38 只在**读了用户 `Launch-2026-10-29-100855623.log`** 之后，5 分钟就定位了真凶：
>
> - `系统版本: 10.0.19044.0` → 测试机是 **Windows 10**，`IsBackdropSupported`(≥22621) 与
>   `IsCornerPreferenceSupported`(≥22000) **都不成立**：云母、DWM 亚克力、DWM 圆角全都不可用，
>   只剩旧版 `SetWindowCompositionAttribute` 的 AccentBlur；
> - `[Material] 窗口外形：窗口区域（内缩 10px / 圆角 16px）` → 我们设的窗口区域**成功了**，
>   所以「磨砂更大」不是区域没设上，而是 **AccentBlur 根本不听窗口区域**，
>   再加上我们给的 `AccentFlags = 0x20|0x40|0x80`（四边延伸）把模糊画到了客户区之外。
>
> **这些信息只在日志里。** 不读日志的任何「修复」都等于掷骰子。

## 1. 日志在哪

| 场景 | 位置 |
| --- | --- |
| 运行时的实时日志 | `<exe 所在目录>\PCL\Log\Launch-<yyyy-M-d>-<HHmmssfff>.log`（`PCL.Core/Logging/LogService.cs` → `StoreFolder`） |
| 应用内导出 | 设置 → 查看日志 → 导出日志（文件名同上，可发给维护者） |
| 崩溃日志 | 同目录；另有 `PCL\Log\Error.log` 记录日志系统自身的异常 |

## 2. 打开后**必看**前 30 行

开头那段 `[基本信息|startup]` 直接决定后面所有结论能不能成立：

```
[INFO] [STA] [基本信息|startup]
版本: Publish 27.1-snapshot-38 (561, native) (x64)
路径: C:\Users\xxx\Downloads\PCLCE For SGU 27.1-snapshot-38(2.15.1).exe
系统版本: 10.0.19044.0 (x64)          ← Win10=19044 / Win11=22621+，决定材质能力
管理员身份: False
```

⚠️ **先确认用户跑的就是你刚构建的那个包**（`版本:` 行里的 `snapshot-XX` 与 `code`）。
曾经出现过「用户测的是上一版、我们以为改动无效」的情况。

## 3. 行格式与 grep 配方

```
[10:08:58.576] [DBG] [STA] [Material] 窗口外形：窗口区域（内缩 10px / 圆角 16px；区域包围盒 (10,10)-(840,490)）
 时间           级别   线程   模块标签   内容
```

| 命令 | 用途 |
| --- | --- |
| `grep "\[Material\]" 日志` | 高级材质：`效果：<选择> → <生效>（<实现方式>）`、`窗口外形：…`、降级原因 |
| `grep "\[PluginHost\]" 日志` | 插件安装 / 加载 / 已应用的功能键（判断功能到底有没有被启用） |
| `grep "\[WARN\]\|\[ERR\]" 日志` | 所有告警与异常（插件、下载、UI 的回退原因都在这里） |
| `grep "\[Control\]" 日志` | 用户到底点了哪些按钮 / 切了哪些页面（复现路径） |
| `grep -c "" 日志` | 注意日志是否只有启动段（后续没有动作 = 用户没进那个页面） |

级别说明：`DBG` / `INFO` / `WARN` / `ERR` —— **`DBG` 会写进日志文件**，
所以自己加诊断日志时放心用 `ModBase.Log(..., ModBase.LogLevel.Debug)`。

## 4. 读不到日志怎么办（Termux / Android 常见）

用户把日志拷进工作区后，文件属主可能**不是当前 Termux 用户**，权限是 `660`：

```bash
ls -l Launch-*.log          # 看到属主 u0_a3xx 与权限 rw-rw----
# → 让用户执行：chmod 644 Launch-xxxx.log      （或直接把内容贴进对话）
```

**读不到 ≠ 可以不读**。先把「拿日志」当成任务的一部分去解决（chmod / 让用户贴内容 / 让用户导出新日志），
不要因为读不到就去猜代码。

## 5. 自己加诊断日志的规范

1. 前缀用模块标签（`[Material]`、`[PluginHost]`…），方便 grep；
2. **状态变化时才打**，不要在渲染路径里每帧刷（否则日志被刷爆）；
3. 凡是「系统调用到底有没有生效」不确定的地方，**读回**结果再打日志
   （例：设完窗口区域用 `GetWindowRgn` + `GetRgnBox` 读回包围盒）；
4. 把「选择 → 生效 → 实现方式 → 降级原因」一次性打全（`MaterialService.AppliedVia` 就是为此加的）。
